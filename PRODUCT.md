# Screening Bridge

Platform: native iOS, built with Xcode 27.1 and SwiftUI. iPhone-first; minimum iOS 26.

An independent cinema programmer prepares a screening, explores potential local partners, reviews collaboration ideas, and saves an editable plan. The approved v3 screen set in the parent project is the visual authority.

The native app has separate sample and live modes. The live starter workflow uses a local authenticated backend for Qloo ranking, OpenAI web research and structured collaboration proposals. It includes native navigation, local draft/plan/evidence persistence, editing, selection, cancellation, recovery, animation, accessibility adaptation and optional haptics. Public browser access, broad coverage, outreach and ticket attribution remain outside this milestone. Provider credentials never belong in the client; the private development build carries only its scoped backend-access token.

Sample partner data is fictional. Live mode is limited to two films, Nitehawk Williamsburg and three starter candidates; results require current identity/source checks and returned Qloo ranking. Screenings and collaborations are hypothetical until agreed by the operator and venues. Live screens use generic illustrations or category symbols, not official posters or fictional business photographs. Saving a plan never sends a message.
